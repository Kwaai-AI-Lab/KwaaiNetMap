# Map v2 — Rust API + React SPA

This branch holds the **second-generation** KwaaiNet map. It is parked, not
deployed: `main` carries the v1 service that actually runs today.

| | v1 (`main`) | v2 (this branch) |
|---|---|---|
| API | Python/Flask on a `health.petals.dev` fork, port 8000 | Rust/Axum, port 3030 |
| Endpoints | `/api/v1/state`, `/api/v1/is_reachable/<id>`, `/metrics` | `/api/stats`, `/api/nodes`, `WS /api/live`, `/health` |
| UI | `kwaainet.html`, one static file, Leaflet + vis.js | React 18 + Vite + Tailwind, d3 force graph |
| Deployed | yes | no |

## Why it is parked

v2 was written in one commit in March 2026 and never finished. Its deploy
workflow was disabled a fortnight later, and the `docker-compose.map.yml` it
expects on the target host was never written. The frontend has not been
touched since the day it landed.

It is kept because the backend is real, working code — it crawls the DHT and
serves live stats — and because `MAP_SERVER_V2_REQUIREMENTS.md` is the design
of record for replacing v1.

**A node's health monitor polls `/api/v1/state`, which v2 does not serve.**
That endpoint has to exist here before v2 can replace v1 anywhere.

## Layout

```
map-server/     Rust API and DHT crawler (was KwaaiNet core/crates/map-server)
apps/map/       React SPA           (was KwaaiNet apps/map)
docker/map-nginx.conf               serves the built SPA, proxies /api/ to :3030
Dockerfile.map-server               builds the API
Dockerfile.map-frontend             builds the SPA into nginx
```

## Building the server

The three `kwaai-*` dependencies come from crates.io at the version this crate
was extracted at, rather than from the KwaaiNet workspace — bump them together.

```bash
cd map-server && cargo build --release
```

`kwaai-p2p-daemon`'s build script needs **protoc**; it downloads one if none is
on `PATH`.

## Running it

`map-server` does not speak libp2p. Its crawler opens a *running node's* p2pd
control socket (`KWAAINET_SOCKET`) and drives that node's DHT connection, so a
`kwaainet` node has to be running alongside it.

| env | meaning |
|---|---|
| `BIND_ADDR` | listen address, default `0.0.0.0:3030` |
| `TOTAL_BLOCKS` | blocks in the model; **default 80**, a 70B-class model |
| `BOOTSTRAP_PEERS` | space-separated multiaddrs |
| `ALLOWED_ORIGINS` | CORS, default `*` |
| `KWAAINET_SOCKET` | p2pd control socket path |

`TOTAL_BLOCKS` is the one that bites: leave it at 80 while serving a 32-block
model and coverage is under-reported by 2.5×.
